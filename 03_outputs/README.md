# Generated SQL Outputs

This directory contains **raw SQL schema files** generated by Hermes during testing phases.

## File Naming Convention

```
round_[N]_[MODEL]_spec_[X].sql
```

Where:
- **N** = Test round number (1, 2, or 3)
- **MODEL** = Model used (sonnet, opus, haiku)
- **X** = Spec variant (a, b, or c)

### Examples

```
round_1_sonnet_spec_a.sql     # Round 1: Sonnet model + Spec A (minimal)
round_1_sonnet_spec_b.sql     # Round 1: Sonnet model + Spec B (balanced)
round_1_sonnet_spec_c.sql     # Round 1: Sonnet model + Spec C (comprehensive)
round_2_opus_spec_a.sql       # Round 2: Opus model + Spec A
round_3_haiku_spec_b.sql      # Round 3: Haiku model + Spec B
```

## File Contents

Each `.sql` file contains:

1. **CREATE TABLE statements** for all entities in the spec
2. **Inline comments** explaining design decisions (if the model included them)
3. **Foreign key constraints** and relationships
4. **Indexes** (if suggested by the model)
5. **Data type choices** and constraints

Example structure:
```sql
-- Order Management System Database Schema
-- Generated by: Hermes (Sonnet model)
-- Date: 2026-05-20
-- Spec: Balanced (480 words)

-- Customers table
CREATE TABLE customers (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    ...
);

-- Products table
CREATE TABLE products (
    ...
);

-- etc.
```

## Workflow

1. **Generate**: Run Hermes with a spec variant → outputs SQL file
2. **Validate**: Test SQL syntax locally (`psql -f filename.sql`)
3. **Score**: Use the quality rubric to rate 0–100
4. **Record**: Log score + metrics to wan.db (see `wan_db_logs/README.md`)
5. **Compare**: Use `diff` or GitHub to compare outputs side-by-side
6. **Analyze**: Look for patterns (which model/spec combo is best?)

## Testing Your SQL Locally

```bash
# Create test database
psql -U postgres -c "CREATE DATABASE hermes_test_db;"

# Load the SQL
psql -U postgres -d hermes_test_db -f round_1_sonnet_spec_a.sql

# Verify tables exist
psql -U postgres -d hermes_test_db -c "\dt"

# Check for errors in the log
psql -U postgres -d hermes_test_db -f round_1_sonnet_spec_a.sql > test.log 2>&1
cat test.log
```

## Comparing Outputs

Use `diff` to see what changed between specs:

```bash
# Compare Sonnet output across spec depths
diff round_1_sonnet_spec_a.sql round_1_sonnet_spec_b.sql > spec_a_vs_b.diff
diff round_1_sonnet_spec_b.sql round_1_sonnet_spec_c.sql > spec_b_vs_c.diff

# Compare models with same spec
diff round_1_sonnet_spec_b.sql round_2_opus_spec_b.sql > sonnet_vs_opus.diff
```

## Scoring Notes

As you review each file, record observations:

- **Hallucinated columns**: Extra columns not in spec?
- **Missing tables**: Required tables missing?
- **Naming quality**: snake_case? Proper ID naming?
- **Constraints**: Are NOT NULL, UNIQUE, FK constraints present?
- **Comments**: Is design documented?
- **Indexes**: Are there indexes on FK and key queries?

Use these observations to populate the quality rubric score in `planning/QUALITY_RUBRIC.md`.

## Version Control

❌ **DON'T commit** actual database dumps or test data
